# 작성자별 관점

작성자는 글이 **무엇을 먼저 다루는지**를 정한다. 단어 수준은 독자(`readers.md`)가 정한다.

| 작성자 | 먼저 쓰는 내용 | 어조 | 자주 빠뜨리는 것 |
|---|---|---|---|
| 기획자 | 사용자가 겪는 문제, 비즈니스 가치, 화면 흐름 | 쉬운 말. 시나리오로 설명 | 예외 상황, 숫자로 된 목표 |
| 개발자 | 동작 방식, 제약, 수치, 코드·설정 | 정확한 용어. 처음 나오는 용어는 한 번 풀어 씀 | 왜 이렇게 했는지, 사용자에게 미치는 영향 |
| PM | 일정, 리스크, 내려야 할 결정 | 판단할 내용과 선택지를 앞에 둠 | 근거 자료, 담당자 |
| 디자이너 | 사용자 경험, 화면 상태, 일관성 | 화면 ID와 상태별로 나눠 씀 | 개발 제약, 예외 화면 |
| QA | 재현 절차, 기대 결과와 실제 결과 | 단계 번호를 붙여 사실만 씀 | 환경 정보(버전, 브라우저, 계정) |

## 예시: 같은 사안, 다른 작성자

사안: 결제 페이지 응답이 느려짐

- 기획자: "결제 버튼을 누르고 3초 넘게 기다리는 사용자가 늘었습니다. 지난주 결제 이탈률이 4%p 올랐습니다."
- 개발자: "결제 API p95 응답 시간이 0.8초에서 3.2초로 늘었습니다. 쿠폰 조회 쿼리가 인덱스를 타지 않아서입니다."
- PM: "이번 주 안에 인덱스를 추가할지 정해야 합니다. 추가하면 배포가 하루 늦어집니다."
- 디자이너: "결제 대기 화면(ORD-030)에 로딩 표시가 없어서 사용자가 버튼을 다시 누릅니다. 로딩 상태를 넣고 버튼을 잠급니다."
