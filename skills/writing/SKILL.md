# 글쓰기

한국어 업무 문서를 쓰는 순서다. 1~4단계를 차례로 밟는다.

## 1. 상황 파악

세 가지를 정한다.

| 항목 | 질문 | 참고 파일 |
|---|---|---|
| 문서 종류 | 무엇을 쓰는가 | `references/doc-types.md` |
| 작성자 | 누구 이름으로 나가는 글인가 | `references/roles.md` |
| 독자 | 누가 읽고, 읽은 뒤 무엇을 해야 하는가 | `references/readers.md` |

- 요청이나 대화에서 알 수 있으면 묻지 않는다.
- 알 수 없는 항목만 한 번에 묻는다. 독자를 알 수 없으면 `references/doc-types.md` 형식표의 "기본 독자"로 쓴다.
- 초안을 보여 줄 때 답변 맨 앞에 `독자: ○○ 가정 (근거)` 한 줄을 적는다. 요청에서 알아낸 독자여도, 기본 독자를 썼어도 적는다. 이 줄은 답변에만 쓰고 문서 본문에는 넣지 않는다.
- 작성자와 독자가 부딪히면 독자를 따른다. 예를 들어 개발자가 임원에게 쓰는 글이면 용어 수준은 임원에 맞춘다.

## 2. 형식 결정

`references/doc-types.md`의 형식표에서 고른다.

- 서술식 / 개조식
- 두괄식 / 미괄식
- 기본 골격(절 순서)

문서 종류에 따로 정한 규칙(스터디 문서, 인프라 문서, SB Description, 개발 문서의 코드, 컨플루언스 페이지)이 있으면 그 규칙이 형식표보다 우선한다.

## 3. 작성

- `references/style-rules.md`의 규칙대로 쓴다. 단어 선택, 문장 리듬, 능동문이 중심이다.
- `references/banned-phrases.md`의 표현은 처음부터 쓰지 않는다.
- 사용자가 이미 손본 문장은 다듬으라는 요청이 없으면 그대로 둔다.

## 4. 자가 점검

초안을 파일로 저장한 뒤 점검 스크립트를 돌린다.

```bash
python3 ~/.claude/skills/writing/scripts/check.py <초안 파일>
# 표준 입력도 받는다
pbpaste | python3 ~/.claude/skills/writing/scripts/check.py -
```

- 스크립트는 금지 표현, 피동 표현, 문장 길이 흐름, 줄표(—), 문장 뒤에 붙은 "구분: 값"을 잡는다.
- 걸린 항목을 하나씩 보고 고친다. 고유명사, 인용문, 화면 문구처럼 바꾸면 안 되는 곳은 그대로 둔다.
- 스크립트가 못 잡는 항목은 아래 점검표로 직접 본다.

### 점검표

- [ ] 독자가 첫 문단(또는 첫 항목)만 읽어도 무엇을 해야 하는지 아는가 (두괄식 문서)
- [ ] 결론 대신 "중요하다", "다양하다" 같은 빈말로 문단을 끝내지 않았는가
- [ ] 숫자, 날짜, 담당자, 화면 ID처럼 구체적으로 쓸 수 있는 곳을 뭉뚱그리지 않았는가
- [ ] 숫자가 결론이나 결정을 받치는가. 개수 세기, 쓸데없는 정밀도, 원문에 없는 숫자를 넣지 않았는가
- [ ] 용어를 처음 쓸 때 독자 수준에 맞게 풀었는가
- [ ] 한 항목에 새 용어가 둘 이상 몰리지 않았는가, 근거 경로·IP는 맨 아래로 뺐는가, 같은 양을 단위 하나로 썼는가
- [ ] 개조식 항목을 명사만 늘어놓는 식으로 줄이지 않았는가 (문서 정보는 예외)
- [ ] 서술식 문서 안의 나란한 사실, 절차, 비교를 개조식이나 표로 바꿀 수 있는지 봤는가
- [ ] 표 칸을 "~합니다" 문장이 아니라 명사형으로 맺는 짧은 개조식으로 썼는가
- [ ] 괄호 안에 구분, 목록, 이유처럼 본문만큼 중요한 내용을 넣지 않았는가
- [ ] 문장 뒤에 붙은 "구분: 값"(URL·경로·명령·"확인:")은 줄을 바꿨는가, 문장 중간에 콜론으로 목록을 붙이지 않았는가
- [ ] (컨플루언스) 패널마다 세 줄 이하이고 주요 내용만 들었는가, 다른 문서를 가리키는 곳에 원문 링크를 걸었는가, 두 줄 넘는 명령·설정은 코드 블록에 넣었는가
- [ ] (개발 문서) 설명에 코드가 필요한 곳에 코드 블록을 넣었는가, 고친 코드는 저장소에서 가져온 diff인가, 블록 위에 파일 경로와 설명 한 줄이 있는가
